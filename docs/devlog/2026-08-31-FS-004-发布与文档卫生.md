## 1. 目标与裁定

本项把“代码能运行”补到“仓库可以形成诚实、可复核的候选发布输入”。Rust 主交付面采用 `0.2.0-rc.1`，不宣称 GA；TypeScript 与 Python 保持各自已有仓库版本，不伪造 registry 发布结果。

发布状态于 2026-08-31 通过官方 registry 接口核验：npm 的 `fastsearch-client` latest 仍为 0.2.0，仓库 0.3.0 待发布；PyPI 无同名已发布包，仓库 Python 0.2.0 仅提供源码安装。示例因此使用仓库相对路径，而不是引用 registry 中不存在的 TS 0.3.0。

## 2. TDD 证据

预先建立的可执行 seam 是：

```bash
python3 scripts/ci/check_release_metadata.py
```

首次执行得到 44/107 项失败，覆盖缺失的 LICENSE、NOTICE、CHANGELOG、Rust 候选版本、Python project URLs、示例 SDK 版本、README 发布说明、13 份历史计划状态和 CI release gate。补齐实现并增加 Cargo.lock 与示例 lock 一致性后，基础门禁为 129/129；携带真实 cargo-about 产物时为 131/131。

脚本还接受 `--third-party-notices PATH`。CI 先执行：

```bash
cargo about generate about.hbs > THIRD-PARTY-NOTICES.md
python3 scripts/ci/check_release_metadata.py --third-party-notices THIRD-PARTY-NOTICES.md
```

因此空清单、未生成清单或元数据漂移都会阻断 `licenses` job，清单通过后才上传为发布制品。

## 3. 交付内容

- 根法律与发布文件：`LICENSE`、`NOTICE`、`CHANGELOG.md`。
- Rust workspace 及 Cargo.lock：`0.2.0-rc.1`。
- TypeScript 0.3.0 / Python 0.2.0 的真实发布说明；Python 增加 Repository 与 Documentation URL。
- example 直接链接仓库 TypeScript SDK，复用共享 `chunkText`/`Chunk`，删除本地重复切块实现。
- SDK 的 base64 fallback 不再要求源码编译环境隐式加载 Node `Buffer` 类型，浏览器/Deno 构建契约更干净。
- 13 份旧计划统一归档并链接唯一活动计划；修复 vector 与部署说明的陈旧状态。

vendor 下已有 LICENSE/NOTICE 保持原样。根 NOTICE 明确 docparse 自有归属文件与 `cargo-about` 生成清单的分工。
