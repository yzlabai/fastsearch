## 1. 交付结果

- `PgStore::signal_vector_search` 将 FS-201 的 ready 信号按类型形成独立 recall list；只读同维、searchable、ACL/filter 可见行。
- `real[]` 在 PG 内临时转 `vector` 做精确余弦扫描，不新增 schema、ANN、扩展或 CDC publication。
- Engine 保留 `keyword:user_text`、`vector:user_text`，额外接入 `vector:ocr`、`vector:asr`、`vector:image_caption`、`vector:image_bytes`；signal `user_text` 不重复计权。
- `SearchHit.sources` 增加省略空值的 `model/model_version` provenance；OpenAPI 与 TypeScript 同步为可选字段。
- `SearchHit.vector` 对多向量命中取最高原始相似分；完整来源和贡献仍由 `explain=true` 展开。

## 2. TDD 证据

1. 先以不存在的 `PgStore::signal_vector_search` 得到编译红灯，再实现真实 PG seam。

3. 真实 Engine 首轮只出现旧两路；接线后 caption-only chunk 能进入结果，三路来源齐全、贡献之和等于融合分、model/version 可见。评审后又增加“已配置 PG 但没有可用信号”的逐位兼容快照，以及三条命中的完整排序、原始分和逐来源贡献 golden。

多表示 golden：`crates/fastsearch-engine/tests/golden/fs202_multi_signal.json`。

## 3. 兼容性与确定性

- 未配置 PG 真源、没有查询向量或没有可用信号时，不追加 recall list，现有两路行为不变。
- RRF 继续忽略权重；具名 `Weights` 继续按稳定 source 键取权重；旧 `Normalized/Weighted` 把原 semantic 总权重均分到实际非空向量路，避免路数膨胀放大总权重。
- PG 每路按余弦距离、collection/doc/chunk 排序；core 继续按 source 字典序累加并以 GlobalId 最终 tie-break。

## 4. 明确限制

- signal `real[]` 当前是精确扫描，无 ANN；适合正确性闭环和中小规模，不宣称生产大规模性能。
- 查询向量与信号向量必须处于同一模型空间；本轮返回 provenance 供审计，但不增加逐请求模型路由。
- 信号生产仍由后续摄取作业面负责；FS-202 只消费已经 ready 的信号。
