## 1. 交付结果

FS-301 的 `ingest_job` 状态机已接入公开 REST 面。调用方可以上传原始文件或提交 `source_uri`、查询
作业状态和派生文档列表；独立 worker 可用专用 capability 更新阶段并写 chunks。server 不解析文档，
不新增产品文档表，身份真源仍是 API key 映射，作业和 chunks 真源仍是 PostgreSQL。

## 2. PostgreSQL 接缝

- `submit_upload` 以 collection/doc_id advisory transaction lock 串行裁定：新建、同 hash
  indexed 去重、同 hash 在途合流、失败/过期重开、异 hash 在途冲突和终态覆盖均保持一文档一行。
- 租约是否有效由数据库 `clock_timestamp()` 判断；queued 的空租约显式 `COALESCE(false)`，避免
  SQL NULL 被 Rust bool 解码失败。
- `GlobalId` 不含 tenant，故文档锁改为全局 `(collection,doc_id)`；上传事务同时检查 job/chunk owner，
  `PgStore::upsert_doc` 在 DELETE 前再次锁定校验。跨 tenant 冲突返回 409，原 chunks 不变。
- `upsert_chunks` 同样按排序后的文档坐标取锁，并拒绝“换一个 chunk_id”混入另一 tenant；与 doc replace
  并发时只允许一个 owner 成功，不能制造混租户文档或阻断后续摄取。
- `get_visible` 与 `list_documents` 在 SQL 内应用 tenant/tag ACL。文档列表由 visible jobs/chunks
  `FULL OUTER JOIN` 派生，使用 `(collection,doc_id)` keyset，不建立第二份权威状态。
- `publish_indexed` 以 owner+epoch+未过期条件锁住 job 行，并跨异步 PG chunks 和派生索引写入持锁；
  成功才标 indexed，失败回滚，使租约到期重领不能穿过旧 worker 的发布窗口。

## 3. REST 与运行配置

- `POST /v1/documents`：multipart `file|source_uri` 二选一，服务端按真实字节计算 SHA-256，原始对象
  使用确定性 key 保存。`wait=auto|never`，auto 仅短暂轮询 worker；200 与 202 响应字段同构。
- `GET /v1/jobs/{id}`：不可见与不存在统一 404；响应包含 stage/profile、创建/更新/完成时间和轮询提示。
- `GET /v1/documents`：collection/state/keyset/limit/counts，输出严格白名单。
- `POST /v1/jobs/{id}/status|chunks`：只接受 worker key；普通 API key 403，错误 job/owner/旧 epoch 409；
  tenant/ACL/collection/doc_id 一律从 job 行恢复，请求体不能覆盖。
- `FASTSEARCH_MAX_DOCUMENT_BYTES` 默认 32MiB，只为上传路由放宽 body 限制；其他路由保持 20MiB。
  超限返回 413 并提示使用 `source_uri`。同步轮询由 `FASTSEARCH_INGEST_SYNC_MAX_BYTES`、
  `FASTSEARCH_INGEST_SYNC_WAIT_MS`、`FASTSEARCH_INGEST_SYNC_MAX_INFLIGHT` 配置。
- `/metrics` 新增上传、去重、失败、同步命中/超时 counters，以及六状态 job 和 dead-letter gauges；
  PG gauge 使用 1 秒按需缓存，连续 scrape 不重复串行查询 `JobStore`。

## 4. TDD 与 review 修复

RED 用例先固定 PG 幂等决策、ACL 派生、无 PG fail-closed、上传 200/202/413、worker fencing 和
OpenAPI 精确字段。双轴 review 后完成以下修复：

- worker chunks 必须存在真实 `PgStore`，不能只写内存派生索引后把 job 标为 indexed；测试改为真实 PG。
- job/document DTO 补齐 stage/profile 和规范时间字段；multipart 独立接受 `media_type`。
- worker 状态从自由字符串改为 serde enum；JSON 解析移到认证、限流、PG/capability 检查之后。
- 全局 body limit 恢复 20MiB，仅上传 MethodRouter 使用文档上限；移除设计外的 `wait=always`。
- 用 `publish_indexed` 关闭“旧 worker 写入中租约过期、第二 worker 重领并双写”的并发窗口。
- 同步补齐 PG/server spec、根架构说明、活动计划、OpenAPI 与摄取指标断言。

复审结果：Standards 与 Spec 均无阻塞缺口；server 单文件较大是既有结构性债务，模块拆分作为后续
独立重构处理，避免在安全协议交付中扩大变更面。
