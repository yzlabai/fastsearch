## 1. 本轮结果

FS-103 闭合了 CDC 的 LSN 语义、多副本首建、跨存储恢复意图和运行健康：

- 生产消费路径不再借用 `Applier` 的事件水位；行事件 LSN 只描述 WAL 消息，持久化检查点与 slot advance 统一使用含 Begin/Commit 的本批最高 commit LSN。
- `ensure_slot` 捕获 PostgreSQL `duplicate_object`，8 个并发实例首建同一 slot 时恰有一个创建、其余按“已存在”成功返回。
- `peek_batch` 同时返回事件、commit LSN、slot lag 字节和确定性死信数；空轮询仍从本地 checkpoint 恢复 last-applied LSN。
- 写穿/本地发布前原子写入 `cdc-batch-intent.json`，persist 后把阶段更新为 `persisted`，slot advance 成功后才删除。启动发现意图时 readiness 阻断，后台常规轮询重放同批并恢复。
- CDC 开启后 `/readyz` 从进程级探针切换为依赖级探针；首轮源轮询、恢复意图、源错误或死信漂移未闭合时返回 503。CDC 未开启时保持原进程级 200 契约。
- `/metrics` 新增 CDC enabled/ready、slot lag、last-applied LSN、last-successful-poll、dead-letter total、rebuild-needed。

## 2. 恢复协议与边界

```text
peek（slot 不推进）
  -> prepare（无派生状态修改）
  -> fsync intent{phase=applying, commit_lsn}
  -> PG 写穿事务 + 本地派生发布
  -> persist(text/vector/checkpoint=commit_lsn)
  -> fsync intent{phase=persisted}
  -> advance slot(commit_lsn)
  -> 删除 intent + fsync 目录
```

这不是 PostgreSQL 与本地文件之间的分布式 2PC。协议提供的是可检测、可阻断和可重放：

- prepare 前失败没有修改派生状态，不产生恢复意图。
- PG 写穿、Tantivy/Turbo 发布或 persist 失败会保留意图；readiness 标记 `rebuild_needed`，slot 未推进，同批按 GlobalId 幂等重放。
- persist 后、advance 前崩溃会重放已持久化批次；upsert/delete/clear 的替换语义保证最终只有一个版本。
- advance 后、删除意图前崩溃时，重启首拍发现 slot 已空，确认源可访问后清除遗留意图。
- 确定性毒丸会推进 slot 以避免全链路停摆，同时累计 dead letter 并保持 rebuild-needed；需从 PostgreSQL 真源重建以消除可能漂移。

本轮没有把 polling 改为 `START_REPLICATION`，也没有宣称任意本地后端存在物理回滚。对 Tantivy commit、Turbo sidecar 等错误，当前保证是持久化意图 + readiness 阻断 + slot 重放；若重复重放仍失败，运维必须从真源重建。

## 3. TDD 与故障覆盖

- 并发建槽：修复前 8 个任务中出现 duplicate-object；修复后 8/8 成功、仅一个返回新建一致点。
- 状态批次：新增公开 `peek_batch`，真实 PG 写入后验证事件数、commit LSN、正 slot lag 与零死信。
- 写穿失败：第二条 embedding 的 PG trigger 注入失败，恢复意图留存且 slot 不推进；移除 trigger 后重放两条成功并清除意图。
- 四阶段崩溃：peek、apply、persist、advance 后分别 drop/restart；peek/apply/persist 会重放，advance 后不重放，最终搜索均恰有一个 GlobalId 且 slot 为空。
- 空轮询状态：pgvector 写穿反馈收敛后，空拍仍报告磁盘 checkpoint 中的最后 commit LSN，不回退为 0。
- readiness：CDC 恢复意图存在时 HTTP 503 并暴露 rebuild-needed；成功轮询后 HTTP 200、scope=dependencies，并带 LSN/lag/成功时间。
