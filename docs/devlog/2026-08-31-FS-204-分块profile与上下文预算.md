# FS-204 开发日志：分块 profile 与上下文预算

> 日期：2026-08-31
> 状态：✅ 完成
> 计划：[FS-204](../plans/2026-08-31-FS-204-分块profile与上下文预算.md)

## 交付结果

1. `ChunkProfile` 集中校验 name/version/target/overlap，并贯通 `fastsearch ingest`、`index-dir`、Rust 纯文本 helper；每条 chunk 的 `metadata.chunking` 可反解所选配置。
2. vendored docparse 增加 geometry-safe overlap：仅复用完整 layout block，bbox/page/heading_path/section_id/char_len 继续来自真实源。
3. TypeScript/Python 分块 helper 同步 profile provenance 与参数校验，并修复文末产生 overlap-only 伪块。
4. MCP、TypeScript、Python 以 `docs/contracts/context-budget-cases.json` 为共享契约，统一 Unicode 字符计数、前向保留、80 字符最小截断门槛，以及 `dropped/truncated/context_chars`。
5. 未设置总预算时，MCP 仍只返回 `hits`，SDK formatter 仍只返回 `content/citations`；不把预算下沉到 Engine/SearchRequest，也不伪造 token 数。

## 关键设计

- profile 是本次摄取的版本化 provenance，不是 collection registry。变更只影响新摄取；旧文档批量重切留给 FS-301 之后的作业面。
- docparse overlap 是上限而非精确值：若尾 block 自身超过上限，本边界不重叠，以引用坐标真实性优先。
- 预算只计算 evidence（MCP `snippet+text`；SDK `highlight+text`），不计算 `[n]`、来源标签和省略号。
- CLI 纯文本分块状态封装进私有 `TextChunker`，调用面只表达 heading/line/finish，集中守住 overlap 尾部不得单独落块的不变量。

## 测试与活入口

- 根 `cargo test --workspace` 全绿；`cargo clippy --workspace --all-targets -- -D warnings` 全绿；CLI `parse` feature 测试与 clippy 全绿。
- docparse：core-only 93 tests；完整 workspace 309 tests；全 workspace clippy `-D warnings`；overlap 坐标 union 与 heading barrier 用例通过。
- TypeScript：29 tests；Python：5 ingest + 18 integration tests；三端读取同一共享预算 fixture；组合参数回归证明 per-hit 先于 total，`context_chars` 按实际保留字符记账。
- 真 server + 真 CLI：DOCX 以 `live-docx` v4、target 16、overlap 4 摄取，REST 命中返回完整 `metadata.chunking`；同一 Markdown 以 target 120/1200 分别生成 63/32 chunks。
- 重建后的真远端 `fastsearch-mcp` stdio 进程在预算 80 下返回 `context_chars=80`、`truncated=1` 与 hit `text_truncated=true`。验证时先发现旧 `target/debug` 可执行文件未重新链接，显式 `cargo build` 后契约生效，未把陈旧产物误判为代码缺陷。
- 双轴复审：Standards PASS；Spec 初审发现 per-hit 后置会让 `context_chars` 高报/误丢命中，补红灯并改为 per-hit 先行后复审 PASS。

## 范围边界

- 不隐式重切已索引文档，不新增 profile 表/API。
- 不跨 heading/table/image/code/list/page 做 overlap。
- 不估 token，不改 Engine/SearchRequest，不新增数据库 schema 或依赖。
