## 做什么 / 为什么

MCP 是文档里点名"Agent 原生（推荐给 LLM agent）"的那张脸，却是**四张脸里最后一张还嵌引擎的**
（CLI 早在 2026-06-28 就改成了纯 REST 客户端）。后果三条：agent 宿主必须与索引同机同文件系统；
**多租户根本用不了**（ACL 是进程级 env 常量，一个进程一个租户）；server 的能力
（嵌入后端、pgvector 直查、限流、审计）一概不共享。

**关键设计判断（沿用 spec，实施时确认成立）**：运行模式是**后端选择**，不是第二套协议——
`handle` 的形状两档一致，只有 `Backend::{Local, Remote}` 的分派不同。这让"两档命中形状必须
逐字段相同"成为可测的断言，而不是口头约定。

## 三个不显然的点

### 1. 能力探测只能认 `GET /v1/collections`

`/openapi.json` 看似更"契约"，但它是**手写静态**的（`openapi_spec()`）、**免认证**、只随 crate
版本变——**不反映本实例配了什么**。真正的实例事实在 `server_vector_info` 里
（`"embedded": s.embedder.is_some()`），随 `GET /v1/collections` 返回。

附带好处：`list_collections` 走 `require_principal` ⇒ **探测顺带验 key**，401 在启动期就报，
而不是等 agent 第一次调用工具才发现。

探测失败 → **拒绝启动**。不猜、不静默回退本地档：猜一个 schema 正是 KB-0.1 修掉的那类谎。

### 2. 远端档**不持有 `AclFilter`**

这不是省事，是不变量 #3 的要求：ACL 已在 server 侧的过滤期落实（SUPERSET 预过滤 + `visible`
精确后过滤）。MCP 再补一层只会产生"两处判权且可能不一致"的第二真源。
出站只发允许清单字段 + `Authorization: Bearer`，测试 `remote_search_sends_no_acl_and_carries_bearer`
直接断言出站 body 里没有 `tenant`/`acl`/`query_image`。

同理，`FASTSEARCH_MCP_TENANT` 在远端档下是**客户端自称的身份**——无意义且危险，
两者同配 ⇒ **拒绝启动**，不合并、不静默取其一。

### 3. 顺手收掉三个洞（都是"未宣称/未声明"这一类）

- **入参允许清单**：`tool_search` 此前把整个 `arguments` 反序列化成 `SearchRequest`，
  于是 `query_image` 能硬传却从未被宣称，而默认 `keyword` 档下 `want_vec` 为假
  ⇒ **图片被完全忽略且毫无提示**。现在未宣称的入参一律拒绝并列出可用字段。
  允许清单与 schema 的 `properties` 由 `schema_and_allowlist_agree` 钉住不漂移——
  这是 C1 的唯一扩展点。
- **本地档 fail-closed**：未设 `FASTSEARCH_MCP_TENANT` 时 `acl = None`
  ⇒ `engine.search(&req, None)` **不做任何 ACL 判定、全库可见**。这与 server 侧
  fail-closed 修掉的是同一类"替调用方猜"。现在要么显式 tenant、要么显式
  `FASTSEARCH_MCP_ACL=all`，否则拒绝启动。
- **两档同配拒启**（见上）。

## 活服务验证（起真 server，实跑二进制）

| 场景 | 结果 |
|---|---|
| 远端档启动 | 探到 `embedded=false backend=brute 真源=none` ✅ |
| `tools/list` | 按实测能力只列 `["keyword"]` ✅（server 没配 embedder） |
| 远端 `search` | 经 REST 返回**投影后的五字段** ✅ |
| `query_image` | 被允许清单拒绝 + 指路 ✅ |
| 本地档未声明可见范围 | 拒绝启动 + 三条改法 ✅ |
| 远端 + `FASTSEARCH_MCP_TENANT` | 拒绝启动 + 二选一 ✅ |

**实跑抓到一个单测没抓到的 bug**：探测读的是 `server.backend`，而 `server_vector_info` 吐的是
`vector_backend` ⇒ 静默变成 `"unknown"`。单测用的 mock 响应是我按记忆手写的、字段名一起错了，
所以自洽地绿着。已修，并把**真实字段名**写进 mock + 加断言钉死。

> 这已经是本仓第二次由"活服务验证"抓到单测漏掉的错（上一次是 fail-closed 的 metrics 畸形输出）。
> 共性都是：**单测的输入是我自己造的，造错了就自洽地绿**。凡是与外部实际响应对接的解析，
> mock 必须照抄真实响应，且断言解析结果而不只是断言"没报错"。

## 遗留

- MCP 仍**只读**（KB-0.3 写入工具）、无上下文预算（KB-0.4）。
- 远端档 `hybrid` 的成色：`embedded:true` 只证明 server 配了嵌入后端，**不**证明向量是语义的
  （`HashEmbedder` 基线也是 `Embedder`，`server_vector_info` 不吐 `caps().semantic`）。
  故描述措辞是"由 server 侧嵌入后端提供"，不得写"语义检索"——等 KB-2.4 的实测 caps。
- 以图搜图仍不宣称：同样等 KB-2.4 把 image/cross_modal 实测 caps 放进 introspection。
- spec §9 的 CI `mcp-server-e2e` job 未加。
