# Devlog · FS-304 作业面故障注入与运维指标

> 日期：2026-09-01 · 状态：✅ 已完成
> 聚焦计划：[FS-304 实施计划](../plans/2026-09-01-FS-304-作业面故障注入与运维指标.md)

## 1. 本轮交付

文件上传改为 `reserve job(source_ready=false) → put reserved URI → ready`。首次对象写入失败时，
job 已在 PG 可见但 worker 不可领取；同一上传使用确定性 URI 修复原 job。替换旧原文时，
`cleanup_source_uri` 持久化至幂等删除成功；如清理失败，系统拒绝第二次异 hash 替换，
避免单值 hint 被覆盖。`ObjectStore` 新接缝有 fail-closed 默认实现，Local/S3 统一校验
provider、bucket、路径和 tenant-scoped key 形式。

worker 将失败分为 retryable、terminal、作业租约丢失和 worker-fatal；server 持久化
`error_retryable`，terminal 立即耗尽重试预算。嵌入 HTTP 错误现在以 `EmbedFailureKind` 类型传递，
不再从错误文案反解状态码。PG connect/claim 断连会丢弃旧 client、指数退避并重建连接，
不会让 worker 进程退出。

死信新增 owner-scoped `POST /v1/jobs/{id}/retry`，MCP 远程档按 capability 暴露 `retry_ingest`。
人工重试清理旧进度、计数、错误和租约，但不替换源文件或 profile。job JSON 新增
`source_ready`、`error_retryable`、`retry_url` 和 `next_action`。

## 2. 可观测性

保留旧 `fastsearch_ingest_failures_total`，新增低基数分类族
`fastsearch_ingest_failures_classified_total{classification="retryable|terminal"}`，避免旧查询失效或
同名指标重复计数。同时新增 source/cleanup pending、active/expired lease、recent worker、
oldest claimable ready age 和 manual retry 指标。最老 ready 年龄只统计退避已到期且当前可领取的作业。
recent worker 由持久化的最近处理者/观察时间派生，完成或失败清除活动租约后仍能反映最近 worker
存活；ready age 从当前可领取时刻而非文档初次创建时刻起算。CDC 另新增 applied batch、applied row
累计值和 recovery-pending gauge，并同时出现在 readiness 快照与 Prometheus 输出。

## 3. 故障演练与验证

- 真实 PostgreSQL/pgvector：验证 source pending 不可领取、terminal 死信、owner retry、
  PG chunks commit 后发布失败的租约重领与 golden 收敛。
- CDC：验证 PG embedding 已写但 derived 缺失的恢复后 vector 命中，以及 apply/persist/advance
  各窗口重放无丢失、无重复、不提前推进 slot。
- 活 worker 进程：运行中停止 PG 容器，观察到 claim/connect 失败进入退避；恢复 PG 后
  原进程重建连接并继续轮询。
- 长连接恢复：对 server 持有的 `JobStore`/`PgStore` 连接执行 `pg_terminate_backend`，同一
  store 实例的下一次访问原位重建 client 并读回真值。
- 环境门禁：PG `executed=49, skipped=0, missing=0`；外部模型 `executed=0, skipped=3,
  missing=0`，因未提供 `FASTSEARCH_EMBED_TEST_URL` 而如实跳过。真实 PG 用例串行执行，避免全局
  DDL/publication 测试之间相互死锁；门禁记账允许 `--nocapture` 诊断日志介于用例名与 `ok` 之间。
- `cargo fmt --all --check`、workspace 严格 Clippy、workspace 全量测试通过。

## 4. Review 修正

Standards / Spec 双轴 review 首轮找到：PG 短断连退出 worker、连续替换覆盖 cleanup hint、
对象 scheme/tenant key scope 校验不完整、嵌入错误字符串分类、公共 trait 源码兼容性、运维指标命名和
作业租约术语问题。以上均已闭环；分类指标经兼容性复核后保留独立名字，并回写计划。

复审继续闭环四项可信度问题：新增同一 job 经真实 worker REST 路由经历 derived 发布失败、人工失败
回报、lease epoch 递增重领并最终 keyword/vector 同版本命中的 T20c 集成测试；为 T20d 补齐公开
batch/row/recovery 指标；`PgStore` 与 `JobStore` 统一复用可重连连接模块；server 摄取计数和权威 job
快照渲染拆入独立运维指标模块，避免路由库继续堆积指标状态机细节。
最终规格复审又补充真实 T20d：在 logical slot 未推进时构造已持久化 recovery intent，重启后走
生产 `consume_once_shared` 重放并 advance，断言 slot 清空、派生索引无重复，以及公开 batch=1、
row=2、recovery-pending=0；Prometheus helper 也收敛为单一实现。
