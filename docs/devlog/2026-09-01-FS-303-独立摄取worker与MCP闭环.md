# Devlog · FS-303 独立摄取 worker 与 MCP 闭环

> 日期：2026-09-01 · 状态：✅ 已完成
> 聚焦计划：[FS-303 实施计划](../plans/2026-09-01-FS-303-独立摄取worker与MCP闭环.md)

## 1. 本轮交付

新增 `fastsearch-ingest-adapter`，把原 CLI 内的 docparse 注册、增强、分块、图片字节收集和 core 映射
移动为唯一共享实现；CLI 只保留 REST facade。adapter 的 `ChunkProfile` 常态可用，解析依赖继续由
`parse` / `parse-ocr` / `parse-tables` / `parse-vlm` 分档控制。

新增独立 `fastsearch-ingest-worker`：每个并发槽单独连接 `JobStore`，使用 PG
`FOR UPDATE SKIP LOCKED` claim；阻塞解析进入 `spawn_blocking`，异步 heartbeat 独立续租。worker 从与
server 同配置的 ObjectStore 取原件，只向 job-scoped worker REST 端点发送无身份 chunk；owner+epoch
失效时停止发布。`parse_profile` 可选择分块参数、图片落点和重解析能力，镜像也能通过
`WORKER_FEATURES` 构建参数选择能力档。

MCP 远端档新增 `ingest_document` / `ingest_status`。工具是否出现由 live server 返回的
`document_ingest` 能力决定，只有 PG jobs、ObjectStore、PG source store 同时可用才宣称支持；本地档不暴露。
`wait=complete` 会在预算内轮询终态，`wait=never` 返回 job 与下一工具提示，超时不会伪装成功。

server 的 worker chunks 契约增加 `store_media=inline|object`，Rust 与 OpenAPI 均拒绝未知字段；身份、
collection 和 doc_id 仍只能从 fenced job 行恢复。retryable failed job 保留轮询提示，而不是误报终态。

## 2. 关键边界

- server、engine、core、text、vector、MCP 和默认 CLI 依赖树均不含 docparse；server 不依赖 worker。
- worker wire DTO 没有 `collection`、`doc_id`、`tenant`、`acl`，对象读取先校验 tenant namespace。
- worker 只直连 PG 领取 durable job；heartbeat、阶段、失败与 chunk 发布全部经 server capability gate。
- 本轮不增加 dataset/source/version/profile 产品对象；完整故障分类与跨阶段 crash matrix 留给 FS-304。

  上传→25 chunks→indexed→search→citation；`ingest_status` 返回 indexed。

## 4. Review 修正

Standards / Spec 双轴 review 找到并已闭环两项状态一致性问题：根 workspace 增加
`default-members`，使根目录默认 `cargo build` 继续保持零 docparse，同时 `--workspace` 仍覆盖 adapter/worker；
adapter 与 MCP spec 同步改为已完成真实链路验收。CI 现直接检查根默认依赖树，并编译 worker 三种重 feature。

收口自查另加固 MCP 文件上传：拒绝带控制字符的 `media_type`，消除 multipart header injection；
文件读取本身以 `max+1` 截断复核，关闭 metadata 检查后的文件增长竞态。对应回归测试已加入。
