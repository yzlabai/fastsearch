# 文档坐标采用全局命名空间

fastsearch 将 `(collection, doc_id)` 定义为系统级全局文档坐标，而不是 tenant 内坐标。现有
`GlobalId`、citation、chunks 主键、删除/替换和派生索引都不携带 tenant；继续允许不同 tenant 使用同一
坐标会造成不可区分的引用和跨租户替换。摄取 job 与所有 chunk 写路径因此获取同一文档 advisory lock，
并在写前拒绝不同 owner；调用方需要给 collection 或 doc_id 加业务命名空间以避免碰撞。

## Considered Options

- 把 tenant 加入所有真源主键、`GlobalId`、citation 和 SDK：语义最直接，但会破坏现有引用格式、索引快照、
  CDC、管理 API 和客户端协议，需要单独的版本化迁移，FS-302 不暗中实施。
- 只让 job 按 tenant 隔离、chunks 保持现状：会允许同坐标混合 tenant 或互相 DELETE，已拒绝。

## Consequences

- job 表新增 `(collection, doc_id)` 全局唯一索引；升级时若已有重复坐标会 fail closed，需先显式迁移。
- 冲突统一返回不含既有 owner/source/error 的 409，不能用于读取另一 tenant 的内容。
- 若未来必须支持 tenant 内同名坐标，应以新版本协议把 tenant 纳入全链路身份，并提供 citation/快照迁移，
  而不是移除当前写前检查。
