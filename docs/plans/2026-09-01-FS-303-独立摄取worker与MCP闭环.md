# FS-303 · 独立摄取 worker 与 MCP 闭环实施计划

> 上游：[迭代开发计划 FS-303](2026-08-30-迭代开发计划.md)、
> [摄取作业面设计 §6](2026-08-25-ingest-job摄取作业面设计.md)。
> 状态：✅ 已完成（2026-09-01）。

## 1. 目标与边界

本迭代交付一条可运行的 `POST /v1/documents → PG job → 独立 worker →
/v1/jobs/{id}/chunks → indexed` 链路，并让远端 MCP 以 `ingest_document` 暴露它。
server、engine、默认 CLI 构建继续保持零 docparse；完整跨阶段故障注入矩阵仍归 FS-304。

不新增身份、dataset/version/profile 控制面，不让 worker 直接写 chunk 真源，也不允许 worker
在回传中指定 collection/doc_id/tenant/acl。租约失效后，heartbeat、状态推进和发布均由现有
`job_id + owner + epoch` fencing 拒绝。

## 2. 模块与依赖裁定

1. 新建轻量 `fastsearch-ingest-adapter`。`ChunkProfile` 与纯映射类型常态可用；docparse
   解析器和增强器只在 `parse` / `parse-ocr` / `parse-tables` / `parse-vlm` feature 下出现。
   CLI 原解析实现移动到此 crate，CLI 仅保留 REST 上传 facade，禁止复制两份解析管线。
2. 新建独立 `fastsearch-ingest-worker`。每个并发槽持有独立 `JobStore` 连接；对象字节通过
   engine 的既有 `ObjectStore` trait 获取，解析后只调用 worker 专用 REST 端点。
3. worker 默认租约 60s、20s heartbeat；空队列退避 500ms 到 5s。解析是阻塞工作，放到
   `spawn_blocking`，heartbeat 在 Tokio 任务中独立续租；一旦续租或阶段推进被拒，停止发布。
4. `parse_profile` 只解析已支持的 chunk 数值/profile 和图片字节策略；OCR/VLM/tables 仍由
   feature + 既有 env 双门控。未知 profile 字段保留为 provenance，不伪造产品化 profile。
5. MCP `ingest_document` 仅远端档可见，接受 `collection`、可选 `doc_id`、`file_path` /
   `source_uri` 二选一、可选 `media_type`/`parse_profile`/`wait`。`wait=never` 原样返回 job 与
   轮询提示；`wait=complete` 在 MCP 超时预算内轮询到 indexed/failed，否则返回非终态与明确
   `job_url`/下一步，不能谎称同步完成。

## 3. 实施顺序

1. 先用测试锁定 adapter profile 校验、CLI facade 等价性和默认依赖隔离，再移动解析实现。
2. 用纯函数/传输测试锁定 worker 配置、无身份 wire DTO、失败分类、租约丢失停止发布；实现
   claim/heartbeat/fetch/parse/publish 主循环。
3. 用 MCP mock HTTP 测试锁定 multipart 字节、source_uri 档、允许清单、同步轮询和本地档不可见；
   同步更新 MCP spec。
4. 在真 pgvector、真实 server/worker/MCP 二进制上验证上传→indexed→search→citation，另验证
   worker 中止/重启后作业可重领收敛。
5. 执行 hot-path、fmt、clippy、workspace test 和双轴 review；修正后回写主计划、spec 与开发日志。

## 4. 验收矩阵

- adapter：CLI 既有 PDF/DOCX/图片字节与 chunk provenance 测试全绿；默认 CLI dependency tree
  不含任何 `docparse-*`。
- worker：真 PG 下并发槽领取不重复；解析期间 heartbeat；旧 epoch 不发布；瞬时失败进入可重试
  failed，确定性解析错误最终按 max_retries 进入 dead-letter；重启可接续领取。
- 安全：worker chunk JSON key 白名单不含 `collection/doc_id/tenant/acl`；对象存储继续校验 tenant
  namespace；worker key 只走现有 capability gate。
- MCP：本地 tools/list 无 `ingest_document`；远端 schema 与允许清单一致；文件 multipart 与
  source_uri 两档均不携带身份；同步终态、异步轮询提示可被 agent 直接使用。
- 全局：`hot-path-isolation`、fmt、clippy `-D warnings`、workspace tests 全绿，活服务端到端有日志凭据。

## 5. 回滚

新 crate、worker 二进制与 MCP 工具均为 additive。停止部署 worker 即停止消费，不影响现有
`POST /v1/index` 和 CLI 客户端解析路径；回滚 MCP 只移除工具声明/分派，不改 job 表。数据库无
破坏性迁移，作业仍以 PG 行为唯一真值。
