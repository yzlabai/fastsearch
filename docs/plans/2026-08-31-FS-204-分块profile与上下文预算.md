## 1. 需求三件套

### 目标用户

维护不同知识库 collection 的开发者，以及要把检索结果安全放入 LLM context 的 Agent 开发者。

### 使用场景

1. 摄取 PDF/DOCX/Markdown 时，调用方按语料为每次 collection 摄取选择块长、重叠与 profile 标识；后来读取 chunk metadata 即可知道文档采用了哪套切分策略。
2. Agent 从 MCP、TypeScript 或 Python 取得同一批命中时，给定总字符预算应保留同一前缀、做同样的单条截断，并拿到明确的 dropped/truncated/context_chars 记账。

### 产品定位关联

闭合活动计划的 M2 末项 FS-204：让“调用方拥有解析”具备可追溯的分块契约，同时让三张 Agent 客户端面不会静默挤爆上下文。

## 2. 范围与裁定

### 做什么

- `docparse-core::ChunkOptions` 增加 geometry-safe `overlap_chars`：只复用完整源 block，绝不为截取半个 block 伪造 bbox；target/overlap 都是字符数。
- `fastsearch ingest` 与 `index-dir` 暴露 `--chunk-target`、`--chunk-overlap`、`--chunk-profile`、`--chunk-profile-version`；`ingest` 同步暴露表格 markdown 渲染。
- CLI、TS、Python 产出的每条 chunk 在 `metadata.chunking` 记录 `chunker/profile/version/target_chars/overlap_chars/table_markdown`。
- profile 改动只影响本次及后续使用该配置的新摄取，不隐式重切已索引文档；批量重跑等 ingest job 作业面完成后再提供。
- MCP、TS、Python 统一采用 Unicode 字符数、80 字符最小保留阈值、按既有顺序前向累加；预算命中时返回 `dropped`、`truncated`、`context_chars`。
- 建立共享 JSON contract cases，三端读取同一输入与预期，防止算法漂移。

### 不做什么

- 不把上下文预算塞进 Engine/SearchRequest，不估算 token。
- 不持久化新的 collection registry 或触发后台重建。
- 不把 overlap 应用于标题、表格、图片、代码、列表，或跨页/跨 section；这些边界必须保住引用语义。
- 不改变未设置总预算时 MCP 和 SDK 的既有运行时返回形状。
- 不新增依赖或 PG schema。

## 3. 接口与深模块决策

### D1：一个 profile 隐藏参数校验与 provenance

Rust CLI 用 `ChunkProfile` 作为小接口，集中校验：name 非空、version > 0、target > 0、overlap < target。它负责生成 metadata，调用路径不重复拼 JSON。

默认 profile 如实区分实现：docparse 路为 `docparse` v1（target 800），纯文本 helper 为 `fastsearch-text` v1（保持各 SDK 既有 target 900；Rust index-dir 采用同档）。显式 profile 名不冒充跨 chunker 算法完全相同，metadata 另有 `chunker` 字段。

### D2：overlap 服从坐标真实性

docparse 只能在完整 layout block 边界重叠。每次因 target flush 时，从旧 chunk 尾部选择总字符数不超过 `overlap_chars` 的完整 block 作为下一 chunk 前缀；若最后一个 block 已超过上限，则本边界 overlap 为 0。page、bbox、heading_path、section_id 都由真实复用 block 得出。

纯文本 CLI/SDK 没有真实版面，继续按精确字符尾部 overlap，bbox 明确为占位零框。

### D3：预算是外层深模块

统一规则只计算 evidence 字段（MCP 的 snippet+text；SDK 对应 highlight+text），不把引用标记和展示来源算作证据字符：

1. 完整命中可放下则保留。
2. 第一条放不下的命中若剩余至少 80 字符，则按 snippet→text 顺序保留前缀、标 `text_truncated`，之后停止。
3. 剩余不足 80 则丢弃该条及尾部。
4. `dropped` 是未返回命中数；`truncated` 是已返回但证据被缩短的命中数；`context_chars` 是实际保留的源字符数（省略号及渲染标记不计）。

SDK 同时设置 per-hit 与 total 时先应用 per-hit 限制，再对实际留下的 evidence 做总预算；per-hit 截断不计入总预算的 `truncated`，避免 `context_chars` 高报或错误丢弃本可放下的命中。

## 4. 用户使用例子

```bash
fastsearch ingest report.pdf --collection annual \
  --doc-id report.pdf --chunk-profile annual-report --chunk-profile-version 2 \
  --chunk-target 1200 --chunk-overlap 120 --chunk-table-markdown
```

```json
{
  "metadata": {
    "chunking": {
      "chunker": "docparse",
      "profile": "annual-report",
      "version": 2,
      "target_chars": 1200,
      "overlap_chars": 120,
      "table_markdown": true
    }
  }
}
```

```ts
const ctx = formatHitsForLLM(hits, { maxContextChars: 2000 });
// ctx.dropped / ctx.truncated / ctx.context_chars
```

```python
ctx = format_hits_for_llm(hits, max_context_chars=2000)
```

## 5. TDD 纵向切片与验收

1. docparse core：两组 target 产生不同边界；overlap 只携带完整 block，两个 chunk 的 page/union bbox/char_len/section 均正确；默认输出不变。
2. CLI parse：`chunks_for_file` 读取 profile 并在所有 chunk 写 provenance；非法 profile 在网络前失败。
3. CLI text：`chunk_text_with` target/overlap 可控、metadata 完整、默认 wrapper 兼容；`index-dir` 把 profile 传到每个文件。
4. TS/Python ingestion：profile metadata 与 Unicode `char_len` 正确，非法 target/overlap/profile 显式报错。
5. 预算共享 contract：完整保留、跨字段截断、剩余不足 80、CJK/emoji 字符计数，MCP/TS/Python 保留相同 citation 集合和三项记账。
6. 无预算兼容：MCP 仍只有 `hits`；TS `formatHitsForLLM` 仍只有 content/citations；Python 新 helper 无预算只返回 content/citations。
7. 真入口：实际 CLI 对 fixture 以两组 profile 产出不同边界且 metadata 可反解；TS/Python 同 fixture contract 全绿；MCP 真二进制或公共工具 seam 验证预算字段。
8. 收口：root fmt/clippy/workspace test、vendor docparse fmt/clippy/core tests、SDK tests、双轴 review 全绿。
