> [摄取作业面设计 §7–8](2026-08-25-ingest-job摄取作业面设计.md)。
> 状态：✅ 已完成（2026-09-01）。

## 1. 目标与边界

本迭代把摄取作业从“正常路径可用”提升为“每个已知故障窗口都有可验证结论”：瞬时故障可重试并
最终收敛，确定性故障明确进入可操作死信，所有崩溃都不能错误地把 job 标为 `indexed`，PG 真值、
派生索引和 CDC advance 的顺序继续满足既有恢复协议。

本项会修正三处现有契约缺口：上传改为先建立不可领取的 durable job、再落原始字节并使其 ready；
失败持久化 `retryable` / `terminal` 分类；死信增加原所有者可调用的人工重试入口。不会引入分布式
事务、通用工作流编排器、生产环境可触发的任意 failpoint，也不改变文档坐标和 ACL 模型。

## 2. 恢复协议裁定

### 2.1 原始字节与 job 交接

文件上传采用 `reserve → put → ready`：server 先以确定性对象 URI 创建或重置
`source_ready=false` 的 job，worker 领取查询只接受 ready job；对象写成功后原子置 ready。
若进程在 reserve 后崩溃，同一请求重试会复用该 job、重写同一对象并完成 ready，不能产生不可追踪
的对象。外部 `source_uri` 在创建前已校验存在，直接以 ready 状态提交。

替换旧原始对象时，待清理 URI 持久化在 job 行；ready 后执行幂等删除并清空标记。删除失败不阻止
新版本被消费，但会通过 gauge 暴露；后续同坐标上传会先重试清理，也为未来维护扫描保留持久化依据。

### 2.2 失败分类与死信

- retryable：对象暂时不可用、网络/超时、embedder 408/425/429/5xx、PG 短断连和租约过期。
- terminal：非法 profile、不可解析/不支持的确定性输入、对象越权/元数据非法、embedder 其余 4xx
  或响应维度/结构错误。
- fencing 冲突不是本 job 的失败：旧 worker 立即停止发布，不覆盖新租约状态。
- retryable 每次增加 `retry_count`，到达 `max_retries` 后进入 dead-letter；terminal 立即进入
  dead-letter。job 响应返回最后一次分类和建议动作。
- `POST /v1/jobs/{id}/retry` 只允许原 tenant、仅对 dead-letter 且 source-ready 的 job 生效，清理
  错误与租约后重新排队；它不绕过 ACL、不替换源文件，也不自动修改 parse profile。

### 2.3 PG、派生索引与 CDC

保持 `PG chunk commit → derived persist/commit → job indexed`。任一步抛错或进程退出，
`publish_indexed` 的 job 事务回滚，作业仍可被 lease reclaim；PG upsert 是幂等替换，重放后以本次
完整 chunk 集合作为真值。CDC 保持 `peek → apply → persist → advance`，advance 前崩溃重放相同
batch，不产生重复可见文档，也不提前移动 slot。

## 3. 公共接缝与兼容性

1. `ObjectStore` 增加确定性目标 URI 与按该 URI 写入的能力；Local/S3 实现校验 scheme、bucket
   和 tenant-scoped key 形式，server 只用已认证 tenant 构造 key，不允许借新接口写出 tenant scope。
   既有 `put` 保留并由新原语实现；新 trait 方法提供 fail-closed 默认实现，不破坏外部实现的源码兼容性。
2. `fastsearch_ingest_job` 只做 additive migration：新增 `source_ready`、`error_retryable` 和待清理
   URI。已有行默认 ready，旧客户端读取不受影响。
3. worker failure wire 新增可选 `retryable`，缺省 `true`，兼容已部署 worker；job JSON 只增加字段。
4. OpenAPI、MCP 状态提示和运维文档同步；人工 retry 是用户面恢复操作，不复用 worker capability。

## 4. TDD 实施与验收矩阵

| 编号 | 故障点 | 预期分类/恢复 | 可观测验收 |
|---|---|---|---|
| T20-raw | reserve 后、对象 put 前退出；对象 put 失败 | retryable，job 不可领取；同请求重试补齐并可领取 | pending-source gauge，最终 indexed |
| T20-claim | claim 后退出或 lease 过期 | retryable/reclaim，旧作业租约全部 fenced | active/expired lease、recent worker gauge |
| T20-parse | 解析前后退出；输入/profile 确定性失败 | 退出可 reclaim；确定性失败直接 dead-letter | terminal failure counter、retry action |
| T20-embed | 429/5xx/timeout 与其余 4xx/坏响应 | 前者 retryable，后者 terminal | 分类持久化，次数与死信一致 |
| T20a | PG chunk 已提交，随后发布失败 | job 仍 embedding；reclaim/upsert 后 indexed，chunk 等于 golden | 无半完成 job |
| T20b | PG embedding 已写、derived 缺失 | CDC/rebuild 恢复，vector 命中 | recovery pending 最终归零 |
| T20c | derived commit 前退出 | job 不得 indexed；重放并 reclaim 后收敛 | keyword/vector 同版本 |
| T20d | persist 后、CDC advance 前退出 | 同 batch 幂等重放，slot 不提前 | batch/row/recovery 指标一致 |
| T20-pg | PG 短断连 | retryable，不错误 indexed | retry counter，恢复后收敛 |
| T20-dead | retries 耗尽或 terminal | actionable dead-letter | owner 可 retry，非 owner 404 |

每条先通过公开 seam 写失败测试，再做最小实现；PG/CDC 项必须使用真实 pgvector + logical
replication，worker 生命周期项使用真实二进制或进程级 harness。最终执行格式化、严格 Clippy、
workspace tests、环境门禁、活服务故障演练和标准/规格双轴 review。

## 5. 运维指标

在保留现有指标名基础上新增：

- `fastsearch_ingest_failures_classified_total{classification="retryable|terminal"}`；既有无标签
  `fastsearch_ingest_failures_total` 原样保留，避免同名指标族同时含总量和分类样本造成 PromQL 重复计数；
- `fastsearch_ingest_jobs_source_pending`、`fastsearch_ingest_jobs_cleanup_pending`；
- `fastsearch_ingest_leases_active`、`fastsearch_ingest_leases_expired`；
- `fastsearch_ingest_workers_seen_recently`；
- `fastsearch_ingest_oldest_ready_age_seconds`；
- `fastsearch_ingest_manual_retries_total`。

高价值告警组合为：ready backlog 持续增长且 recent workers 为零；expired leases 增长；dead-letter 或
cleanup pending 非零；CDC recovery pending 长时间不归零。指标只使用低基数 state/classification 标签。

## 6. 回滚

数据库迁移均为 additive，旧 worker 将新失败字段缺省为 retryable；新 server 可在停止新 worker 后
回滚，已有 ready job 仍可被旧实现处理。`source_ready=false` 的预留 job 必须由新 server 修复或人工
取消，回滚前先确认该 gauge 为零。人工 retry 路由和新指标可独立移除，不删除历史 job 数据。
