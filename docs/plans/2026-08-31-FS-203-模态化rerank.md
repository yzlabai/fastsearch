# FS-203：模态化 rerank、保序降级与可解释原因

> 日期：2026-08-31
> 状态：已完成
> 上游：[下一阶段迭代开发计划 FS-203](2026-08-30-迭代开发计划.md#fs-203-kb-23-模态化-rerank)、[知识库引擎迭代计划 KB-2.3](2026-08-24-知识库引擎迭代计划.md#kb-23-按模态选重排)
> 影响模块：`fastsearch-rerank`、`fastsearch-engine`、`fastsearch-server`、TypeScript SDK

## 1. 要做什么

把当前“只接收 query/candidate 字符串”的 rerank 接口升级为能力自描述、输入类型显式且可以诚实降级的深模块：

- `Reranker` 公开 `text/image/cross_modal` capability，并接收带类型的 query/candidate 输入；
- reranker 可以显式返回“本批次无信息量”，而不是伪造一组全零分；
- Engine 在 query/candidate 模态不支持、query 分词为空、后端报错或输出非法时，保持 rerank 前的融合顺序与数量；
- `explain=true` 时，每条命中用稳定状态/原因码说明 applied 或 skipped；
- `LexicalOverlapReranker` 明确是 text-only baseline，等分时保留原融合相对顺序。

用户仍通过现有 `rerank:{model,top_k}` 请求重排，不增加控制参数。响应只在 `explain=true` 且请求了 rerank 时增加可选 `rerank_explain`。

## 2. 为什么

当前接口有三个已证实的错误形态：

1. 纯标点或分词器不识别的 query 会得到全零分，随后按 GID 排序，覆盖原融合顺序；
2. text-only reranker 无法判断 image-only 或混合模态候选是否适用，只靠 Engine 对空 query 的特判；
3. reranker 服务错误直接让整个 search 失败，而且 Engine 已先按 `rerank.top_k` 截断，无法回到未重排结果。

rerank 是可选精度档，不应降低基础检索的可用性或正确性。适用性和“是否真的产生排序信息”必须成为显式契约。

## 3. 接口与深模块决策

### D1：类型信息进入 rerank seam

`fastsearch-rerank` 增加：

- `RerankInputKind = Text | Image | TextImage`；
- `RerankInput`：携带 kind，以及可用的 text/image 字节；
- `RerankCaps { text, image, cross_modal }`，通过 `admit` 集中判断整批 query/candidate 类型组合并返回稳定拒绝原因；
- `RerankOutcome = Scores(Vec<f64>) | Skipped(RerankSkipReason)`。

Engine 不再通过“query 字符串是否为空”猜测后端能力。后续接远端多模态 reranker 时可以沿用同一 seam；本轮不实现真实图片重排服务。

### D2：无信息量由最了解分词规则的 reranker 裁定

`LexicalOverlapReranker` 的 tokenizer 留在模块内部。query 无 token 时返回
`Skipped(EmptyQueryTokens)`，不暴露 tokenizer，也不让 Engine 重复实现一套判断。

### D3：降级是事务式的

Engine 先保留完整融合命中，再复制 `rerank.top_k` 窗口给 reranker。只有能力匹配、返回数量正确、全部分数有限时才提交重排结果；其他情况丢弃临时窗口，继续使用原命中。

因此 skipped/error 路径与 `rerank=false` 在 ID、融合/BM25/向量分、数量、顺序上逐位相同。后端错误是可用性降级，不再升级为 search 失败。

### D4：rerank 等分沿用融合顺序

rerank 分只提供新的有序证据；两条得分相同表示后端没有区分它们。等分时保留 rerank 前的确定性融合顺序，不再按 GID 二次覆盖。

### D5：解释是加法兼容字段

`SearchHit` 增加可选 `rerank_explain`：

```json
{
  "status": "skipped",
  "model": "lexical",
  "reason": "empty_query_tokens"
}
```

稳定 reason code：`unsupported_query_modality`、`unsupported_candidate_modality`、
`empty_query_tokens`、`backend_error`、`invalid_backend_output`。成功时 status=`applied` 且省略 reason。
只有 `explain=true` 且请求 rerank 时返回，默认响应不变化。

## 4. 模态裁定

- 非空文本 query → `Text`；只有图片/显式视觉向量 → `Image`；文本与查询图片同时存在 → `TextImage`。
- 空白文本且没有图片/显式向量仍是 `Text`，由 reranker 自己判定 `EmptyQueryTokens`，不得误报为图片能力不支持。
- chunk 的 `kind.modality()` 为 Text/Image 时映射到对应候选类型；Audio/Video 在本轮没有 rerank 输入协议，按 unsupported candidate 降级。
- `text=true` 允许 Text→Text；`image=true` 允许 Image→Image；`cross_modal=true` 允许不同类型或 TextImage 组合。
- LexicalOverlap caps 固定 `{text:true,image:false,cross_modal:false}`。混合候选中只要一条不支持，整批跳过，避免把不同计分空间拼在同一排序里。

## 5. 不做什么

- 不接神经 cross-encoder，不新增进程内模型或依赖。
- 不从 PG/对象存储批量读取图片字节；真实图片 reranker 接入时再按其批处理协议实现。
- 不改变 recall、融合、ACL、Filter、rerank 请求字段或默认关闭语义。
- 不把 rerank 失败计作请求失败；但 explain 与后续 metrics 必须能看见降级。

## 6. 用户使用例子

请求：

```json
{
  "query": "!!!",
  "rerank": {"model": "lexical", "top_k": 20},
  "explain": true
}
```

命中保持未重排顺序，并附：

```json
{
  "rerank": null,
  "rerank_explain": {
    "status": "skipped",
    "model": "lexical",
    "reason": "empty_query_tokens"
  }
}
```

## 7. TDD 纵向切片与验收

已确认测试 seam：`Reranker` 公共接口、`Engine::search`、真实 REST `/v1/search`。

1. **rerank 模块**：Lexical caps 是 text-only；纯标点返回 `EmptyQueryTokens`；正常文本返回对齐候选数的分数。
2. **image-only**：带 lexical rerank 与不带 rerank 的命中快照逐位相同，explain 原因为 unsupported query。
3. **混合候选**：文本 + 图片候选不被局部重排或 GID 覆盖，原因是 unsupported candidate。
4. **无 token**：纯标点 query 与 rerank=false 逐位相同，reason=`empty_query_tokens`。
5. **服务错误**：注入返回 error 的边界 adapter；search 仍成功且逐位等于基线，reason=`backend_error`。
6. **非法输出**：长度不等或 NaN/Inf 不污染结果，reason=`invalid_backend_output`。
7. **有效重排**：相关文本仍能前移；相同 rerank 分保留原融合相对顺序；status=`applied`。
8. **契约**：OpenAPI/TS 将 `rerank_explain` 标为可选；`explain=false` 响应不含该字段。
9. **活服务**：实际二进制中纯标点请求返回 200、顺序与无 rerank 相同并带 skip 原因；正常文本重排仍 applied。
10. **收口**：fmt、clippy `-D warnings`、workspace tests、TypeScript tests、既有 relevance golden 全通过；双轴 review 无硬问题。

## 8. 完成摘要

- D1–D5 已全部落地；没有新增模型依赖、请求字段或 PG schema。
- Reranker 模块现在独立拥有 capability、整批准入、输入类型和无信息量裁定；Engine 只做模态映射与事务式提交。
- 五类降级原因、有效重排、等分二级排序和深分页均有公共 seam 回归测试。
- REST/OpenAPI/TypeScript/Python agent metadata 契约已同步；默认响应仍省略 `rerank_explain`。
- 真实二进制经 `/v1/index` + `/v1/search` 验证 skip 与 applied 两路。完整测试和 review 证据见[开发日志](../devlog/2026-08-31-FS-203-模态化rerank.md)。
