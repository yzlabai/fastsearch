## 1. 本迭代边界

本项只交付 `fastsearch-pg` 内的一张普通 PG 作业表、纯状态机和 `JobStore`。上传、查询 API、
worker 二进制和 MCP 工具分别留给 FS-302/303/304；本项不在 server 中建立内存作业真源。

`fastsearch_pub` 已由 FS-201 定夺为 chunks-only，作业表不进入 publication，也不依赖任何 PG 扩展。

## 2. 公共 seam

- `IngestState`：六个权威状态及合法迁移判断。
- `NewIngestJob` / `IngestJob` / `JobLease`：创建参数、持久化快照、带 fencing token 的领取结果。
- `JobStore::connect(url, table)`：独立于 `PgStore` 的连接；后续 worker 每个并发槽可各持一条。
- `ensure_schema`：在既有 schema advisory lock 下执行 additive、幂等的一表 DDL。
- `enqueue` / `get`：FS-302 可复用的最小写读 seam；同文档重复创建返回显式 conflict，幂等/覆盖策略仍归 FS-302。
- `claim` / `heartbeat` / `advance` / `finish` / `fail`：领取与全部回写均校验
  `job_id + lease_owner + lease_epoch`；返回 `false` 表示 fencing 拒绝。
- `retry_backoff_ms(retry_count, jitter_basis)`：确定性的指数退避，抖动由稳定输入决定并封顶。

公共时间值使用 Unix epoch 毫秒。策略在 Rust 侧确定，SQL 只负责持久化调用方给出的租约/重试时刻。

## 3. 状态与租约约束

- 正向链：`queued → parsing → chunking → embedding → indexed`。
- 任一非 `indexed` 状态可失败；纯状态机接受 `failed → queued`，但持久化重开必须结合 hash/在途状态决定，
  因而明确由 FS-302 的幂等上传事务实现，不允许 worker 用 `advance` 自行重开。
- claim 只领取到期的 `queued` / 可重试 `failed` / 租约过期的处理中作业，原子增加 epoch 并置为 `parsing`。
- heartbeat 不改变状态；advance 必须声明期望旧状态与目标状态，SQL 再校验当前状态，防并发越级。
- `indexed` 终态不可再失败或领取；死信由 `failed && retry_count >= max_retries` 派生，不增加第七状态。

## 4. TDD 验收矩阵

| 编号 | 自动化断言 |
|---|---|
| FS301-U1 | DDL 仅一个 `CREATE TABLE`，含六状态、tenant/ACL、lease/retry 列和四个索引 |
| FS301-U2 | DDL 不含 publication、extension、身份/产品对象列；`lease_owner` 只解释为 worker 租约持有者 |
| FS301-U3 | claim SQL 含 `FOR UPDATE SKIP LOCKED`、重试上限、到期租约和 epoch 自增 |
| FS301-U4 | heartbeat/advance/finish/fail 全含 owner+epoch fencing；advance 含期望旧状态 |
| FS301-U5 | 纯状态机只接受规定迁移；dead-letter 为派生判断 |
| FS301-U6 | 退避确定、含稳定抖动且封顶；非法表名/派生索引超长 fail closed |
| FS301-P1 | 两个独立连接并发 claim 得到不相交集合 |
| FS301-P2 | 租约过期可重领且 epoch 增加；旧 owner/epoch 的 heartbeat/advance/finish/fail 均返回 false/None |
| FS301-P3 | 重试耗尽后不再被 claim，dead-letter 可观察 |
| FS301-P4 | 作业表不在 `fastsearch_pub`；既有 publication 经 chunks schema 收敛后仍不含作业表 |
| FS301-P5 | 从最小旧表执行 additive DDL，旧行保留且新列默认值正确；并发 ensure_schema 无竞态 |
