## 1. 要做什么

在 `fastsearch-server` 暴露原始文档上传、作业状态、文档派生列表和 job-scoped worker 写入；
所有权威状态仍在 PG `ingest_job + chunks`，原始字节只进既有 ObjectStore。

本项不在 server 内解析、不创建 worker 进程、不新增产品对象/版本表，也不做预签名 PUT 或分片会话；
独立解析 worker 与 MCP 闭环归 FS-303。

### 1.1 为什么现在做

FS-301 已建立可靠的作业状态机，但调用方仍只能提交预切好的 chunks：原始文档没有统一入口，Agent
无法查询处理进度，worker 也只能借用普通 `/v1/index` 而存在身份覆盖风险。本项把“原始对象、作业真源、
派生 chunks”串成最小安全协议，使后续独立 worker 可以只关注领取和解析，同时确保 tenant/ACL 始终来自
上传者身份而不是 worker 请求体。

## 2. 已裁定行为

- worker 写 chunk 使用 `/v1/jobs/{id}/chunks`；tenant/ACL/collection/doc_id 全从 job 行恢复，请求体不能覆盖。
- 适配器下沉与独立 worker 延后 FS-303；FS-302 只交付其安全写入协议。
- ObjectStore 继续由 Engine 持有，不拆 crate；server 读取 `source_uri` 全量字节计算 SHA-256，不信任调用方 hash。
- 同文档覆盖不保留版本；新 job 行继续保持一文档一行。
- 默认上传上限 32 MiB；`FASTSEARCH_MAX_DOCUMENT_BYTES` 同时约束 multipart/source_uri 读取和对象存储。
- 小文档同步等待只是轮询 worker 结果，server 不解析：默认 1 MiB、3 秒、最多 32 个等待者；无 worker 时诚实退化 202。

## 3. 公共 seam

### 3.1 PostgreSQL

- `JobStore::submit_upload(NewIngestJob) -> UploadResolution`：同一事务实现新建、同 hash 去重/合流/重开、
  异 hash终态覆盖、异 hash 在途冲突；`GlobalId` 不含 tenant，因此同一 collection/doc_id 的所有权
  全局唯一，跨 tenant 同名上传直接 409，不能进入会覆盖 chunks 的第二个作业。
- `JobStore::get_visible(job_id, AclFilter)`：不可见与不存在同为 `None`。
- `JobStore::list_documents(DocumentListQuery, AclFilter)`：从可见 chunks 与 jobs FULL OUTER JOIN 派生，
  `(collection, doc_id)` keyset 稳定排序，不建文档表。

### 3.2 REST

- `POST /v1/documents`：multipart `collection`, optional `doc_id`, one of `file|source_uri`, optional
  `parse_profile`, `wait`；200/202 与在途内容冲突 409 返回 `IngestJobResponse`，跨 tenant 的全局坐标所有权
  冲突返回脱敏纯文本 409；413/422/503 语义固定。
- `GET /v1/jobs/{id}`：ACL 不可见返回 404。
- `GET /v1/documents`：字段严格白名单，支持 collection/state/keyset/limit/counts。
- `POST /v1/jobs/{id}/status`：仅 worker key；job+owner+epoch fencing；heartbeat/阶段推进/失败。
- `POST /v1/jobs/{id}/chunks`：仅 worker key；从 job 恢复身份与文档坐标，共用 `/v1/index` 写入内核，
  成功后才能 finish indexed。

## 4. TDD 纵向切片

1. **PG 幂等事务**：六种决策表逐项真实 PG 验证，竞争提交不产生第二行。
2. **PG 可见读取**：跨 tenant/tag 不可见；派生列表同时覆盖 chunk-only、job-only、两侧都有。
3. **无 PG fail-closed**：五个路由均 503；上传在消费 body 前拒绝。
4. **上传**：身份 ACL、对象字节/hash/provenance、同构 200/202、同 hash 去重、异 hash 冲突/覆盖、上限 413。
5. **查询**：job 404 防枚举；列表字段白名单、游标和过滤确定。
6. **worker 协议**：普通 key 403；错误 epoch 409；请求体身份字段无效；成功写入后 indexed，失败前不提前完成。
7. **契约与活服务**：OpenAPI 精确字段测试；真实 server+PG+本地 ObjectStore 用 curl 跑上传→轮询/列表。

## 7. 调用示例

上传后按 `job_url` 轮询；`wait=auto` 只在文档不超过同步阈值时短暂等待 worker，超时仍返回同构 202：

```bash
curl -sS -X POST http://127.0.0.1:8642/v1/documents \
  -H 'X-API-Key: alice' \
  -F 'collection=kb' -F 'doc_id=guide.md' -F 'wait=auto' \
  -F 'file=@README.md;type=text/markdown'

curl -sS -H 'X-API-Key: alice' \
  http://127.0.0.1:8642/v1/jobs/job_01...

curl -sS -H 'X-API-Key: alice' \
  'http://127.0.0.1:8642/v1/documents?collection=kb&counts=true'
```

worker key 只能携带 lease epoch 和处理结果，不能指定 tenant/ACL/collection/doc_id：

```bash
curl -sS -X POST http://127.0.0.1:8642/v1/jobs/job_01.../chunks \
  -H 'X-API-Key: worker-secret' -H 'Content-Type: application/json' \
  -d '{"lease_job_id":"job_01...","lease_owner":"worker-a","lease_epoch":1,"chunks":[{"chunk_id":1,"kind":"paragraph","text":"...","page":1,"bbox":{"x0":0,"y0":0,"x1":1,"y1":1},"char_len":3}]}'
```
