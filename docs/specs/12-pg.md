# spec · fastsearch-pg

> 模块 #3，依赖：fastsearch-core。阶段 P1。上游：[产品设计 §2.3/§2.4](../plans/2026-06-24-产品设计文档.md)。
> 状态：**已落地 v2.3**（含 FS-302 上传幂等、ACL 派生查询与发布 fencing，Docker pgvector:pg17 真机验证；见 §7）。

## 1. 目的与范围

Postgres 真源接入层：

- **Schema/DDL**：`fastsearch_chunks` 主表、派生的 `{chunks_table}_signal` 多表示子表、独立的
  `fastsearch_ingest_jobs` 摄取作业表、索引与 chunks-only 逻辑复制 publication（幂等 additive DDL）。
- **Chunk ↔ 行映射**：core `Chunk` → SQL 参数（写入）；DB 行 → `Chunk`（读取/CDC 解码复用）。
- **写路径**：doc_id 级替换（DELETE WHERE collection,doc_id + 批量 INSERT），以及跨文档的 chunk
  批量读取/upsert/ACL 删除、文档分页和 tenant scope collection 删除。
- **客户端**：`PgStore` 管 chunk/signal 真源；独立 `JobStore` 管摄取调度，避免 claim/heartbeat 与检索连接互相串行化。

**不做**：CDC 解码（fastsearch-sync）、检索（fastsearch-text/vector）、pgvector ANN 查询的相关性逻辑（仅提供向量列读写）。

**可移植硬约束**：DDL 只用 pgvector 扩展（`CREATE EXTENSION IF NOT EXISTS vector`）+ 逻辑复制，**不依赖任何需 `shared_preload_libraries` 的原生扩展**（N1b）。

## 2. 数据结构与映射

- 表结构见产品设计 §2.3。列：`collection,doc_id,chunk_id,kind,text,page,bbox(jsonb),heading_path(text[]),section_id,char_len,modality(text NOT NULL DEFAULT 'text'),media(jsonb),tenant,acl(text[]),metadata(jsonb NOT NULL DEFAULT '{}'),searchable(boolean NOT NULL DEFAULT true),embedding(halfvec/可空),embed_model,updated_at`，主键 `(collection,doc_id,chunk_id)`。
  - **多模态（MM2a/MM2b，已实现）**：`modality` 由 `kind` 派生落列（过滤下推优化）；`media jsonb` 承载 `MediaRef`（不含 inline 字节）。**旧 `image_meta` 列已移除**，INSERT 14 参数，`media` 用 `$12::text::jsonb`（同 bbox 的 text→jsonb 强制转换）。
  - **时间列（MM2c-time，已实现，Docker 验证）**：`time_start_ms/time_end_ms bigint NULL`，由 `chunk.media.time` 派生落列（写侧反规范化，读路径 `time` 仍由 `media` 恢复，与后过滤同源）。`col_kind` 纳入这两列 → 时间区间过滤**精确 SUPERSET 下推**（`time_start_ms >= $n` 等），与 modality/page 同构；后过滤 `PgVecRow` 仍取 `media.time` → 两端同源、守不变量 #5。INSERT 16 参数。
  - **inline 字节列（MM2c-bytes，已实现，Docker 验证）**：`media_bytes bytea NULL`（PG 真源，承载 `AssetPointer::Inline` 的小裁图字节）。`Chunk.media_bytes` 字节通道 + `ChunkRow` 往返 + INSERT 17 参 + fetch SELECT 携带；**`PgStore::fetch_media_bytes(collection,doc_id,chunk_id)`** 供媒资网关按需直查（字节是真源、引擎派生层不持）。sync CDC 不搬字节（复制流只搬指针，§4.2）。字节生产者经 **`upsert_doc`** 落 PG；当前 `/v1/index` 在配置 PG 时同样调用该真源写路径，但其 REST DTO 不接收 `media_bytes`，因此 inline 字节仍须由可携带该字段的库/内部写入者落库。设计见 [MM2c-bytes+MM6-inline 媒资服务设计](../plans/2026-06-27-MM2c-bytes与MM6-inline媒资服务设计.md)。
  - **通用调用方字段（2026-07-23）**：`metadata` 原样往返、`searchable` 控制派生索引成员资格；`ensure_schema` 用 additive `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 升级旧表，旧行分别得到 `{}`/`true`。INSERT 现为 20 参数，publication 列清单同步收敛到新真源列。
- 向量维度按集合配置（建表时定 `vector(N)`/`halfvec(N)`）。MVP 允许 embedding 可空（外部later 回填）。
- **FS-201 多表示子表**：表名由 `format!("{chunks_table}_signal")` 派生并再做 identifier 校验；主键为
  `(collection,doc_id,chunk_id,signal_type)`，保存 `status/model/model_version/artifact_hash/body_hash/signal_text/embedding real[]/embedding_dim/error/updated_at`。
  不加外键、tenant/ACL 或 ANN 索引；引用完整性由 PgStore 同事务回收与 `orphan_signal_count` 审计保证。
- **FS-301/FS-302 摄取作业表**：一行对应全局 `(collection, doc_id)`（见 [ADR-0001](../adr/0001-文档坐标采用全局命名空间.md)；旧 tenant-scoped 索引仅为 additive 兼容），只含与 chunk 同构的
  `tenant + acl` 身份字段、原始对象 provenance、六状态、进度、lease owner/epoch、heartbeat、retry/error 和时间戳。
  死信由 `state='failed' AND retry_count>=max_retries` 派生，不是第七状态。作业表是普通 PG 表，不依赖扩展、
  不进入 `fastsearch_pub`；chunks schema 收敛会移除误加入 publication 的作业表。
- 映射函数（纯函数，可单测）：
  - `chunk_columns() -> &[&str]`：列名顺序（写入用）。
  - `insert_sql(collection_table) -> String`：参数化 INSERT。
  - `delete_doc_sql() -> String`：`DELETE ... WHERE collection=$1 AND doc_id=$2`。
  - `ddl(cfg) -> Vec<String>`：建扩展/表/索引/publication。

## 4. 行为规约

- **doc_id 级替换**：`upsert_doc` 在一个事务里先 `DELETE WHERE collection,doc_id` 再批量 INSERT，保证原子（CDC 侧看到 delete+insert）。
- **幂等 DDL**：`ensure_schema` 可重复调用。
- **REPLICA IDENTITY**：表用默认（PK）即可捕获删除键；publication 覆盖该表。
- **Publication 单表契约**：`fastsearch_pub` 永远只发布 chunks 主表，`chunk_signal` 不进流；`ensure_schema` 的
  `ALTER PUBLICATION ... SET TABLE` 会收敛误加的旁表。列清单排除 `embedding/embed_model/updated_at` 的值，但 PG 仍可为只改排除列的 UPDATE 生成事件；
  反馈环的真正阻尼是 `set_embedding` / 信号写入的 `IS DISTINCT FROM` 幂等守卫。列清单要求 PG 15+。
- **信号作废规则**：`user_text/ocr/asr` 绑定 `md5(chunks.text)`；`ocr/asr/vlm_caption/image_bytes` 绑定 inline 字节或
  `media.asset` 工件 hash。漂移时只将相应类型标为 `stale`并清向量，保留 model/text/hash 审计信息；规则来自 `SignalType` 穷尽 match。
- **信号生命周期与原子性**：`upsert_doc/upsert_chunks` 在原写事务内作废漂移信号；doc 替换只回收消失的 chunk_id，不误删仍有效的视觉信号。
  `delete_doc/delete_collection/delete_chunks_visible` 仅对实际删除的 chunk 同事务回收信号，ACL 仍只由 chunks 主表判定。
- **信号召回**：只读 ready、同查询维度、父 chunk searchable 的非 `user_text` 信号；`real[]::vector` 做每路独立窗口的精确余弦扫描，ACL/filter 与主向量直查同样采用 SQL 超集 + Rust 精确复核。
- **`searchable=false`**：PG 行继续存在并可由读取/管理 API 访问；CDC sink 必须把对应 gid 从全文和向量派生索引删除。
- **chunk 管理事务**：batch upsert/delete 各自在单个 PG 事务内执行；upsert 冲突行只有 tenant
  相同时可覆盖，否则整个 batch 返回 conflict。
- **不可见即缺失**：chunk delete 和文档分页的 tenant/ACL 条件在 SQL 内执行；未授权和不存在使用相同结果。
- **collection owner scope**：删除只匹配认证身份 tenant；返回实际删除的 GlobalId 与受管对象 URI，
  供 server 精确清理派生索引和对象。重复删除返回空集合。
- **写穿幂等守卫**：`set_embedding` 的 `WHERE ... AND (embedding IS DISTINCT FROM $1 OR embed_model IS DISTINCT FROM $5)`——值未变 → 0 行更新 → 不空转复制（与列清单互为防线）；`clear_embedding` 仅在 `embedding` 非空时更新。
- **CDC 批量写穿**：`write_embeddings_atomically(&[EmbeddingWrite])` 先校验全部向量，再在单个事务内执行 set/clear；任一项失败显式 rollback，不暴露半批 embedding。
- **作业领取**：一个 CTE 以 `FOR UPDATE SKIP LOCKED` 选取 source-ready 的可重试/租约过期行，原子置 `parsing`、写入完整作业租约并递增 `lease_epoch`；多 worker 不会取得相同的 `job_id + lease_owner + lease_epoch`，预留但尚未落原始字节的行绝不领取。
- **作业 fencing**：heartbeat/advance/finish/fail 都匹配 `job_id + lease_owner + lease_epoch`，且拒绝已过期租约；advance 还匹配期望旧状态。
- **状态规则**：正向链为 queued→parsing→chunking→embedding→indexed；非 indexed 可失败。纯状态机允许
  failed→queued，但持久化重开必须结合内容 hash/在途状态，由 FS-302 上传事务实现，worker 的 `advance` 不得自行重开。
  完成必须发生在 chunk/派生写成功之后。
- **输入 fail-closed**：新作业要求非空 ACL、64 位十六进制 SHA-256、正数 max_retries 和 JSON object profile；重复文档显式 conflict，幂等/覆盖策略由 FS-302 决定。
- **上传幂等事务**：`submit_upload` 以 collection/doc_id advisory transaction lock 串行化裁定；
  同 hash 的 indexed 作业直接去重、在途作业合流，failed/过期租约可原行重开；异 hash 在途返回 conflict，
  终态则原行替换。租约有效性使用 PostgreSQL `clock_timestamp()`，不信任应用机时钟。
- **原始字节交接**：文件上传先写 `source_ready=false` 的 durable reservation，再按确定性 URI
  落对象，最后由 job_id+URI+hash fence 置 ready；同请求重试补齐崩溃窗口。替换旧源时
  `cleanup_source_uri` 持久化到删除成功，不能只靠进程内 hint；hint 未清空前拒绝
  第二次异 hash 替换，防止单值 hint 被覆盖后泄漏更早对象。
- **失败/死信**：`error_retryable` 持久化最后分类；retryable 增加一次 retry_count，terminal
  立即把预算置满。`retry_dead_letter_visible` 仅对 ACL 可见、source-ready 的 dead-letter 原子重排，
  清空错误与租约但不修改源/profile。
- **连接恢复**：`PgStore`/`JobStore` 保留连接配置；长连接已关闭时丢弃旧 client 并原位重建，
  使 server 与 worker 持有的同一 store 实例在 PG 重启后可继续收敛。
- **全局坐标所有权**（[ADR-0001](../adr/0001-文档坐标采用全局命名空间.md)）：公开 `GlobalId` 不含 tenant，因此 document advisory lock 只取
  `(collection,doc_id)`；`submit_upload` 同时检查既有 job/chunk owner，`PgStore::upsert_doc` 在 DELETE
  前再次锁定并检查；`upsert_chunks` 按排序后的文档坐标获取同一锁，校验整份既有文档 owner 和批内
  tenant 一致。跨 tenant 同名坐标返回 conflict，旧 owner 的 chunks 保持逐字段不变。
- **ACL 派生读取**：`get_visible` 在 SQL 内先应用 tenant/tag 可见性，不可见与不存在同为 `None`；
  `list_documents` 从可见 jobs/chunks `FULL OUTER JOIN` 派生文档视图，以 `(collection,doc_id)`
  稳定 keyset 排序，不另建产品对象表，也不暴露 ACL/tenant/source_uri。
- **发布 fencing**：`publish_indexed` 先以 `job_id + lease_owner + lease_epoch`+有效期锁定 job 行，并跨异步 chunks/派生索引写入
  持有该行锁；成功后在同一事务置 indexed。租约到期后的其他 worker 必须等锁，因而不能在旧 worker
  发布中途重领并产生双写；写入失败则回滚状态，不提前完成。
- **健壮**：连接/SQL 错误上报不 panic；bbox/heading_path/acl 的 (de)serialize 失败显式报错。

## 6. 测试用例

**单元（无需 PG，必跑）**：
1. `ddl()` 含 `CREATE EXTENSION IF NOT EXISTS vector`、建表含全部列与主键、publication 语句、`halfvec(384)` 维度正确。
2. `insert_sql()`/`delete_doc_sql()` 形态正确（占位符数、WHERE 条件）。
3. Chunk → 参数行：bbox→jsonb 字符串、heading_path→text[]、acl→text[]、kind→snake_case 字符串、可空 tenant/embedding 处理。
4. 行 → Chunk：往返一致（含中文、含 ':' 的 doc_id、空 heading_path）。

**集成（需 PG，env-gated，`DATABASE_URL` 未设则跳过/ignore）**：
5. ensure_schema → upsert_doc(3 chunk) → fetch_doc 得回 3 个、字段一致。
6. upsert_doc 替换：同 doc 再 upsert 2 个，fetch 得 2 个（旧的被删）。
7. delete_doc 后 fetch 空。
8. batch get 保持输入顺序和缺失槽；chunk upsert 往返 metadata/searchable。
9. ACL 文档分页完整且稳定；不可见 chunk 删除返回 false。
10. collection 删除只影响 owner tenant，重复调用幂等。
11. 两个独立 JobStore 并发 claim 得到不相交集合，stage/finish 全程 fencing。
12. 租约过期可重领且 epoch 增加；旧 owner/epoch 的 heartbeat/advance/finish 返回 false。
13. 重试耗尽形成可观察 dead-letter 且不再领取；旧作业表 additive 升级保留行。
14. 作业表误入 publication 后，chunks schema 收敛恢复 chunks-only。
15. 上传六种幂等/覆盖决策只保留一行，并发同 hash 提交只创建一行；queued 的空租约与 PG 时钟判定均可处理。
16. job/document 读取在 SQL 内执行 ACL；列表覆盖 job-only、chunk-only 和两侧都有，游标顺序稳定。
17. job-scoped 发布在 chunks 写成功后才 indexed；过期 epoch、错误 owner、中途写失败或跨 tenant
    全局坐标冲突不能完成作业，且发布持锁时过期任务不可重领。
18. source-pending 行不可 claim，URI/hash fence 后可领；terminal 失败立即 dead-letter，非 owner
    不可重排，owner 人工 retry 恢复 queued。
19. PG chunks 已提交后注入发布失败，job 仍 embedding；租约过期重领并重复 upsert 后，最终 chunks
    与字面 golden 完全一致且 job 才 indexed。
